# i18n — двуязычный интерфейс студии

Интерфейс студии написан по-русски. Этот слой добавляет второй вариант —
английский — и переключает написание по выбору пользователя.

Переключатель: **профиль → Настройки → Язык**: `Русский` / `English` / `Оба`.
Выбор хранится в тех же настройках, что тема и размер шрифта (`vp-user-prefs`),
поэтому отдельного хранилища нет.

| Режим | Что видно |
|---|---|
| `ru` | исходный русский текст, слой не работает (сборка не грузит словарь) |
| `en` | английский перевод |
| `both` | двойное написание: `Проекты · Projects` |

## Как это работает

Компоненты **не переписаны**. После отрисовки клиентский слой один раз обходит
DOM и подменяет:

- текстовые узлы;
- подписи `title`, `placeholder`, `aria-label`, `aria-description`, `alt`.

Дальше он следит за `MutationObserver`: React перерисовал список, сменился
роут, пришёл ответ API — новые узлы тоже переводятся. При переключении на
русский оригиналы возвращаются из памяти (WeakMap), поэтому обратный переход
не теряет текст.

Словарь грузится **динамически и только для не-русского языка** (`provider.tsx`
импортирует `dom.ts` через `await import()`). Русская сборка остаётся по весу
такой же, как была.

Что специально не трогается: `script`, `style`, `textarea`, `code`, `pre`,
`contenteditable`, узлы с `translate="no"` или `data-i18n-skip`.

## Файлы

```
web/src/i18n/
  index.ts          публичные экспорты (I18nProvider, useLang, translateText)
  provider.tsx      провайдер: читает язык, следит за событиями, грузит runtime
  lang.ts           тип Lang, чтение/запись vp-user-prefs, событие LANG_EVENT
  translator.ts     чистое ядро: словарь + `{}`-подстановки (без DOM)
  dictionary.ts     склеивает messages/*.json в один словарь
  dom.ts            обход и подмена DOM, восстановление русского
  translator.test.ts тесты ядра
  tools/extract.mjs поиск строк в исходниках (для разработки)
  messages/*.json   сами переводы: плоские пары «строка из кода» → «перевод»
```

`messages/` разбит на части по экранам (shell, canvas, studio, admin,
orchestrator, misc), чтобы файлы оставались обозримыми. Для сборки разбиение
не важно — `dictionary.ts` склеивает всё в один объект.

## Как добавить или поправить перевод

1. Найти место в разметке. Ключ словаря — **точный текст из кода** (пробелы по
   краям не важны, внутренние пробелы схлопываются).
2. Добавить пару в подходящий `messages/*.json`:

```json
{
  "Сохранить": "Save",
  "Шаг {} из {}": "Step {} of {}"
}
```

3. `{}` — подстановка любого фрагмента (число, имя). Количество `{}` в ключе и
   значении должно совпадать. Для подписей с числом-данными это главный способ:
   `"Скачано {} из {}"` → `"Downloaded {} of {}"`.
4. Проверить, что в значении нет кириллицы и нет пробелов по краям.

### Найти непереведённые строки

```bash
node web/src/i18n/tools/extract.mjs --missing
```

Скрипт разбирает `web/src` через TypeScript AST, отбрасывает комментарии и
печатает TSV: `строка \t вид \t файл:строка`. Без `--missing` — все найденные
строки. Новые строки из-за этого не появляются сами: разметку по-прежнему
пишут по-русски, перевод — отдельными данными.

## Ограничения

- **Данные пользователя не переводятся.** Названия проектов, темы, тексты
  промтов, сообщения чата — это содержимое, а не интерфейс. Слой меняет только
  те строки, что есть в словаре, поэтому данные остаются как есть.
- **Текст, нарисованный в `<canvas>`**, слою недоступен (немного мест в
  канвасе/плеере).
- **Числа и даты из `toLocaleString("ru-RU")`** остаются в русском формате
  (`1 284`), даты с названиями месяцев переведены отдельными шаблонами в
  `messages/runtime.json`.
- **Вспышка русского текста** на первой отрисовке: статический экспорт отдаёт
  русский HTML, перевод применяется после гидратации.
- **`both`** удлиняет подписи примерно вдвое — режим для сверки, не для работы.

## Проверка

```bash
# тесты ядра
node --test web/src/i18n/translator.test.ts

# типы
node web/node_modules/typescript/bin/tsc --noEmit -p web/tsconfig.json

# полнота: строки в исходниках, которых нет в словаре
node web/src/i18n/tools/extract.mjs --missing
```
