## Модель данных (контракт между шагами)

Семейство = одна карточка в меню выбора модели:

```json
{
  "id": "seedance-2-0",                 // стабильный id семейства (без слэшей)
  "label": "Seedance 2.0",              // что видит человек
  "brand": "ByteDance",
  "media": "video",                     // video | image
  "desc": "…",
  "modes": [
    {
      "id": "t2v",                      // стабильный id режима внутри семейства
      "label": "Текст → видео",
      "kie_id": "bytedance/seedance-2", // id в API kie.ai
      "task_type": "text-to-video",     // taskType из /api/v1/models
      "api": "jobs",                    // jobs | veo | runway | suno | pay52 | …
      "fields": [ {"name","label","kind","options","default","min","max","max_items","hint","required"} ],
      "pricing": {"unit": "sec", "rules": [{"when": {...}, "credits": 41}], "default": 41, "note": "…"},
      "constraints": ["…"]
    }
  ]
}
```

Правила слияния в семейства (обязательны к соблюдению):

- Семейство — по бренду и базовому названию без служебных суффиксов (`Pro`, `Standard`, `Fast`, `Lite`, `Mini`, `Draft`, `Turbo`, `Image to Video`, `Text to Video`, `Reference to Video`, `Motion Control`, `Extend`, `1080p/4K upscale`, `Video Edit` и т.п.).
- Внутри семейства каждый суффикс/тип задачи становится РЕЖИМОМ, а не отдельной карточкой.
- Если варианты различаются только входом (текст / картинка / первый+последний кадр / референсы / видео на входе) — это режимы одного семейства.
- Если у варианта свой эндпоинт и своя механика (например `veo/extend`, `veo/get-1080p-video`, `seedance-2-5-draft`) — это тоже режим семейства, с полем `api`/`constraints`.
- Не сливать модели разных брендов и разные поколения (Kling 2.6 и Kling 3.0 — разные семейства; Kling 3.0 Pro/Turbo/Omni — режимы одного семейства 3.0).
- Ничего не терять: каждый `id` из `/api/v1/models` попадает ровно в одно семейство и ровно один режим. Неизвестные настройки помечать `hint: "неизвестно"`, но режим и цены сохранять.

## Цены (деньги — отдельный контур, важнее всего не ошибиться)

- Студия показывает цену в ДОЛЛАРАХ, не в кредитах. Формула: `usd_client = usd_kie × 1.25` (наценка студии 25%).
- `usd_kie` берётся из `pricingDesc` живого API (там уже есть $ рядом с кредитами) или из официальных доков; 1 кредит kie.ai = $0.005. Никаких «примерно» — цена должна зависеть от конфигурации так же, как в прайсе kie.
- Ценозависимые настройки обязаны учитываться: разрешение (480p/720p/768P/1080P/2K/4K), длительность (за секунду или фикс), тир (lite/fast/quality/standard/pro/turbo), вход с видео vs без (`Total = Price × (Input + Output)` против `Price × Output`), режим (draft upgrade наследует биллинг источника), число дополнительных изображений (например первые 5 бесплатно), per-generation vs per-second.
- В каталоге у каждого режима должна быть таблица правил в USD: `{"unit":"sec|gen|image|1k_chars","usd_rules":[{"when":{...},"usd_kie":0.31,"usd_client":0.3875}],"usd_default":...,"markup":1.25,"note":"формула словами"}`. Правила — из прайса, а не из головы.
- Не путать: кредиты можно оставить внутренним полем для леджера, но UI и API-оценка показывают доллары с наценкой 25%.
- Где цена неизвестна — писать «неизвестно» и не выдумывать; таких мест сейчас 4 модели.
