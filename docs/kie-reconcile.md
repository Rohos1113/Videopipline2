## Этап 1. Живой API ↔ семьи аналитика ↔ прайс

- Живой API: 253 модели, из них медиа **181** (видео 100, картинки 81). С 13.11 добавились 2 текстовые (`gemini-4-hydrogen`, `-openai`), медиа не менялись.
- Семьи: **72 семьи / 182 режима**, 182 уникальных `kie_id`, покрытие 181/181, дублей 0, потерянных 0. Один «лишний» id — `bytedance/seedance-1.5-pro`: есть в доках и таблице, но в живом `/models` его нет (модель недоступна по ключу). Это ожидаемо и помечено `in_live_api: false`.
- Смешения поколений в семьях нет (0). Все `taskType` совпадают, кроме одного: `ideogram/v3-text-to-image` в kie.ai числится «Text to Video» — это баг метаданных kie.ai, семья правильно отнесена к картинкам.
- Цены: 171 из 182 режимов с ценой; все распарсенные кредиты на месте в `pricingDesc` (0 расхождений в обе стороны). Замечания к единицам/арифметике — 8, из них реальные:
  - **4 режима Seedance 1.0** (`bytedance/v1-pro-*`, `v1-lite-*`): в семьях единица `gen`, а в прайсе цена за секунду. Backend берёт правильную единицу из прайс-json (`sec`) и считает по секундам — на продукт не влияет, но в `docs/kie-model-families.json` единица неверная (P2, аналитик шаг 7).
  - `video/upscale`: в описании пара 6 кредитов ↔ $0.0075 не сходится (6 кр = $0.03) — либо это цена за единицу апскейла, либо парсер склеил разные строки. В прайс-json попало `$0.0075/6 кр`, у режима цены нет. Требует ручной сверки с докой (P2).
  - Hailuo 2.3: в `pricingDesc` округления 50 кр → $0.26 (а не $0.25) и 80 кр → $0.39 (а не $0.40). Разница 1 цент, в прайс-json зафиксировано как есть (P3).
  - `wan/2-2-animate`: флаг «нет за секунду» ложный — в описании прямо «per video-second» (проверка не считает это дефектом).
- «Семьи ↔ прайс»: 38 отличий, все — дубли строк прайса, разбитые по разрешению/длительности (Runway, Topaz, Nano Banana Pro, WAN 2.6 и т.п.) либо округления. **Деньги одинаковые.** Исключение: `wan/2-7-image` / `wan/2-7-image-pro` — в семьях правила перепутаны (у базовой модели оказалось 12 кр, у pro — 4.8). Цена в продукте берётся из прайс-json (правильная), но сам `kie-model-families.json` в этом месте неточен (P2).

## Этап 2. Семьи ↔ каталог backend

### 2а. Структура каталога — PASS
`GET /catalog` отдаёт 81 карточку: 72 семейства + 9 аудио. Дубликатов id нет, пустых подписей нет, `family_id` совпадает с `id` у всех медиа. Сверка с `docs/kie-model-families.json`: 0 пропавших карточек, 0 расхождений по label/brand/media/режимам/полям/constraints/docs_url. Расхождения `pricing`: 16, но все — форма записи: `with_video: false` превращается в правило без ключа, `with_video: true` → `_has_videos`; единицы `1m_tokens` ↔ `tokens`, `mp` ↔ `megapixel`. Цены те же до 4 знаков.

Старые 33 записи: id не потеряны, `build_payload` не изменился, кредиты те же. `estimate` для них изменился только добавлением полей `usd/usd_client/markup` — обратная совместимость сохранена.

### 2б. Цена через `/estimate` — FAIL
Проверил 182 дефолтные конфигурации и 227 вариантов (все опции ценозависимых настроек, переключатели, крайние значения). Правила считаются кодом `app/services/kie_catalog.py`.

**Корневая причина №1.** В правилах цены есть ключи `mode` и `sound`, а в форме таких полей либо нет, либо они называются иначе (`model`, `audio`, `generate_audio`). Функция `_find_rule_field` знает только `resolution/tier/audio/upscale/from_resolution`, поэтому такие правила **не срабатывают никогда**:
- `mode` не маппится — 13 режимов (Veo 3.1 generate/extend, Hailuo 2.3, Ideogram V3/Character, GPT Image 1.5, Flux Kontext, Grok Imagine Image);
- `sound` не маппится — PixVerse V6 (4 режима), Kling 3.0 Omni (3 режима: 4 из 5 правил мертвы), Seedance 1.5 pro.

**Корневая причина №2.** У полей без дефолта (`sound`, `duration`, `mode`, `quality` с `default: null`) UI не отправляет значение, а правила требуют его явно. Пример: Kling 2.6 i2v, длительность 10 с — цена остаётся $0.39 (5 с без звука), хотя должна быть $0.7875.

**Корневая причина №3 (данные шага 7).** У 24 режимов нет полей вовсе (схема не распарсилась): Kling 2.1 Master/Pro, Kling 2.5 Turbo, Kling 2.6 Motion Control, PixVerse, Runway, WAN 2.5/2.6/2.7, HappyHorse video-edit. Цена у них всегда равна дефолту-заглушке, а настройки недоступны. Ещё у 13 режимов есть поле разрешения в прайсе, но нет resolution-поля в форме (Hailuo 02, Kling AVATAR, OmniHuman 2.0, Seedream 5 Pro, Nano Banana 2 Lite, GPT Image 2.6 economy, Kie upscale).

Итого недостижимых правил: **62 режима целиком (24 — нет полей, 13 — `mode`, 13 — нет поля разрешения, 4 — `sound`, 6 — токенные/неизвестные, 1 — длительность, 1 — зависит от входного видео) + 7 режимов частично** (Kling Omni, Seedance 1.5 pro).

**Что видит пользователь (DOM, живые клики):**

| Модель / режим | Настройка | Показано | Должно быть |
|---|---|---|---|
| Veo 3.1 generate | model=lite / 720p | $0.375 | $0.1875 |
| Veo 3.1 generate | resolution=4k (fast) | $0.375 | $1.125 |
| Veo 3.1 generate | model=quality | $0.375 | $1.5625 |
| Veo 3.1 extend | model=quality | $0.375 | $1.5625 |
| GPT Image 1.5 t2i/i2i | quality=high | $0.025 | $0.1375 |
| Flux 1 Kontext edit | model=max | $0.0312 | $0.0625 |
| Kling 3.0 Omni i2v | resolution=1080p | $0.47 | $0.6315 |
| Kling 3.0 Omni i2v | audio=вкл | $0.47 | $0.6315 |
| Kling 2.6 i2v | duration=10 | $0.39 | $0.7875 |
| Seedance 1.5 pro | звук вкл | $0.11 | цена должна вырасти |
| PixVerse V6 (4 режима) | quality/звук | не меняется | цена по правилам |

Всего: **9 режимов с неверной ценой в 16 конфигурациях + 6 режимов, где цена не меняется при смене дорогой настройки**. Это одна причина — можно починить в одном месте: научить `_find_rule_field` маппить `mode → model/generation_type/quality/tier` и `sound → audio/generate_audio`, а полям `sound/duration/mode/quality` проставить дефолты (или в `estimate` подставлять дефолт из правил). Владелец: backend шаг 9 (`app/services/kie_catalog.py`).

Дополнительно: megapixel-модели (`qwen-image`) backend считает правильно (1.39776 MP × $0.02 = $0.0375…$0.0524), но UI-константа `PENDING_UNITS` в `web/src/lib/model-settings.ts` помечает `megapixel` как «цена уточняется» — интерфейс скрывает уже посчитанную цену (P1, UI).

### 2в. DOM (пикер, панели, сценарии) — FAIL по доступности
- **Видео:** в пикере все 37 подписей семейств, но строка «Veo 3.1» — это пресет outsee «Veo 3.1 Lite» ($0.50, 720p), а не семейство Veo 3.1 с 4 режимами ($0.03). Остальные 36 семейств — настоящие KIE-строки, число режимов в подписи совпадает с API.
- **Картинки:** 6 семейств не находятся вовсе (Nano Banana 2.1, Nano Banana 2 Lite, Nano Banana Pro, GPT Image 1.5, GPT Image 2.5, GPT Image 2.6), ещё 3 (Nano Banana, Nano Banana 2, GPT Image 2) находятся только как пресеты outsee с чужими ценами. Итого **10 семейств каталога недоступны в UI** — ровно то, что чинит task-15. Дубль имени «Nano Banana 2» в дампе подтверждён.
- Счётчики брендов в пикере не сходятся: видео 40 строк при 37 семьях (3 строки — пресеты), картинки 28 при 35 семьях.
- Панель «Параметры»: у обычных режимов набор полей совпадает с API. Проблемы: у `ideogram-v3/edit` не отображается `mask_url`; у 6 режимов без полей UI показывает настройки, которых у режима нет (WAN 2.6 t2v/v2v/flash-i2v/flash-v2v, PixVerse t2v/extend/r2v, Kling 2.6 motion-control) — значения уйдут в никуда, payload их не содержит.
- Сценарии в живом UI подтвердили ошибки цены: Kling 3.0 Omni 1080p и «звук» — $0.47 без изменения; Kling 2.6 i2v 10 с — $0.39 без изменения; Seedance 1.5 звук — $0.11 без изменения; GPT Image 1.5 в пикере нет, проверить панель нечем.
