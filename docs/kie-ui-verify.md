## 3. Цены — что не так

### 3.1. Правила цены ссылаются на поля, которых в режиме нет

Механика: в UI цена считается по правилу `usd_rules`, где ключ правила = имя поля формы.
Если такого поля (или значения) в режиме нет, правило не срабатывает никогда, и остаётся
`usd_default_client`.

- **76 режимов** имеют хотя бы одно недостижимое правило; **63 режима** — все правила мёртвые,
  цена не меняется вообще.
- Мёртвые ключи: `resolution` (43 режима), `mode` (15), `duration` (13), `sound` (9),
  `token_kind` (4), `max_mp` (3), `from_resolution`/`upscale` (по 1).
- Примеры недобора (default = самый дешёвый тариф):
  `veo-3-1/generate` $0.375 вместо $2.3125 на quality+4K;
  `kling-2-1/master-*` $1.575 вместо $3.15 (10 c);
  `hailuo-2-3/i2v-pro` $0.1875 вместо $0.5625;
  `kling-3-0/video` $0.0944/с для всех разрешений вместо $0.4719/с на 4K;
  `minimax-h3-image/t2i` 4K — $0.0112 вместо $0.0344 (`max_mp` не поддержан);
  `pixverse-v6/*` $0.025/с вместо $0.115/с.
- Причины и владельцы:
  1. **Имена полей не совпадают с ключами правил**: `sound` ↔ `audio` (Kling 3.0 omni),
     `sound` ↔ `generate_audio` (Seedance 1.5 pro), `sound` ↔ `generate_audio_switch`
     (PixVerse), `mode` ↔ `model` (Veo 3.1: в правиле `mode`, в форме `model` со значениями
     `veo3_lite`/`veo3_fast`). Владелец: бэкенд `kie_catalog._match_usd_rule` + прайс.
  2. **Тир зашит в семью, а правило требует поле `mode`** (`hailuo-2-3` pro/standard,
     `kling-avatar`, `veo-3-1/extend`) — правило мёртвое, надо разложить цены по режимам
     или добавить дефолт-правило. Владелец: прайс/каталог.
  3. **Нет поля вообще** (`resolution` нет в `happyhorse/video-edit`, `grok-imagine-video/extend`,
     `runway/*`, `wan-2-6/t2v` и др.) — правило есть, ручки нет. Владелец: контракт полей
     (`docs/kie-model-families.json`) либо прайс (убрать недостижимые условия).
  4. **`token_kind` и `max_mp` в `estimate_usd` всегда false** — 4 режима gpt-image-2-6
     (flare/sunburst) без цены «цена уточняется», 4K у minimax-h3-image и kie-image-upscale
     считается как дешёвый тариф. Владелец: бэкенд.
- Отдельный случай **`kling-2-6/i2v`**: поле `sound` есть, но без default. Пользователь
  выбирает 10 c и не трогает звук — уходит `{duration:"10"}`, правило `{duration:"10",sound:false}`
  не срабатывает (в значении `null`), цена остаётся $0.3937 вместо $0.7875. Двойной недобор.
  Владелец: бэкенд (`_match_usd_rule`: отсутствующий bool должен читаться как false) + UI
  (слать в estimate значения по умолчанию, а не только тронутые).

### 3.2. Живые замеры цены в UI (перекрёстно с отчётом по ценам)

Параллельно в этой же сессии сняты 194 замера по 56 семьям из того же дампа
(`web/.tmp-verify/ui_compare.json`; отчёт — [docs/kie-pricing-verify.md](kie-pricing-verify.md)):
**182 UI = API**, 6 расхождений UI и **5 залипших цен**.

- Залипшие цены (UI показывает старую цену, API считает новую):
  `happyhorse` t2v/i2v/r2v — при 1080p и 15 c в шапке $2.72, а `/estimate` отдаёт $4.50
  (использована ставка 720p); `kling-4-0` keyframe-flash и r2v-flash — $3.19 вместо $0.53
  (в расчёт уехала чужая/старая длительность). Похоже, `kieValues` не успевают/не полностью
  применяются к локальному расчёту — владелец: UI (`estimateSettingsUsd`/`kieValues`).
- Расхождения UI: `gemini-omni/character` и `ideogram-v3/remix` показывают **$0.00** вместо
  «цена уточняется»; `gemini-omni-flash-1-2/extend` $0.38 против $0.12; `nano-banana` и
  `nano-banana-2` — $0.15 против $0.03/$0.07 (взята цена другого пресета — следствие
  подмены строки в пикере); `veo-3-1/generate` $0.50 против $0.38.
- Причина 63 расхождений «формула против API» в том же отчёте — та же, что выше:
  `sound` (40 кейсов), `mode` (19), `video` (2), `max_mp` (2).

### 3.3. Что с ценой в порядке

- 178/182 режимов имеют цену; без цены 4: `gemini-omni-character`,
  `ideogram/v3-remix`, `omnihuman-1-5/human-identification`, `omnihuman-1-5/subject-detection`.
- Наценка 25 % и перевод кредитов ($0.005/кредит): 0 ошибок в 182 режимах.
- `price_from_usd` каждой семьи = минимум по режимам; «от $X» в пикере совпадает с каталогом
  (34 видео + 25 картинок).
- 71 расхождение правил с `docs/kie-prices-usd.json` — **только нормализация**:
  `with_video: false/true` → `_has_videos` и отбрасывание false-условий; числа и ставки совпадают.
- Семантика «от $X»: это минимальная **ставка за единицу**, не минимальный чек. Для 28 семей
  с `unit=sec` «от $0.01» (Seedance 2.0) означает $0.01/с, реальный чек за 5 c 720p — $1.28.
  Так подпись честна формально, но вводит в заблуждение — решение за продуктом.

## 4. Бэкенд: каталог ↔ контракт ↔ прайс

- 72 семьи / 182 режима / 990 полей совпадают с контрактом 1:1 (0 расхождений).
- 182 уникальных `kie_id`, каждый ровно в одном режиме; нет потерянных и лишних.
- `build_mode_payload`: 174/182 через `api=jobs` отдают `{model: kie_id, input: ...}`, 8 —
  другие API (veo/runway/suno и т.п.). Утечек ключей в payload 0, «не доезжающих» настроек 0,
  чужое поле из другого режима отбрасывается во всех 152 проверенных режимах с полями.

## Что не проверено и почему

1. **Цена в шапке после кликов** — в моём дампе 52 расхождения цены по умолчанию из-за
   накопленного состояния формы (длительность 15 c). Прицельные живые замеры сделаны отдельно
   (см. 3.2): 182 цены UI совпали с API, но 5 залипших и 6 расхождений остались. Окончательная
   приёмка цены — за отдельным отчётом по ценам после фиксов.
2. **Фактическая смена значения** (чип меняет значение, повторное открытие показывает
   выбранное) — в дампе нет повторного открытия панели.
3. **Невалидные значения в UI** — проверены только на бэкенде (`validate_mode_values`),
   ошибки в интерфейсе не снимались.
4. **Семьи HappyHorse / HappyHorse 1.1 / Veo 3.1** — данные дампа сели не туда, ждём переснятия.
5. **8 семей без открывшейся панели** и **10 скрытых** — перечислены выше, это дефекты,
   которые сейчас правит UI-агент (task-15).
